Exsited's form builder lets you create tailored data-collection forms for customer portals, supplier onboarding workflows, and internal processes — without writing a single line of code. You can combine multiple field types, apply conditional logic to show or hide fields dynamically, and configure automated actions that trigger when a form is submitted.

## Opening the Form Builder

<Steps>
  <Step title="Navigate to Custom Forms">
    Go to **Configuration → Custom Forms** and click **New Form**.
  </Step>
  <Step title="Name and describe your form">
    Enter a **Form Name** and an optional **Internal Description**. The form name is displayed to users who complete the form, so keep it clear and specific.
  </Step>
  <Step title="Add fields">
    Drag fields from the left-hand **Field Library** onto the form canvas. Rearrange them by dragging into the desired order.
  </Step>
  <Step title="Configure each field">
    Click any field on the canvas to open its settings panel on the right. Set the label, placeholder text, help text, and whether the field is required.
  </Step>
  <Step title="Apply validation and conditional logic">
    Add validation rules and conditional display logic as needed (see sections below).
  </Step>
  <Step title="Preview, save, and assign">
    Use the **Preview** button to test the form, then click **Save**. Assign the form to a portal or workflow to make it available to users.
  </Step>
</Steps>

## Available Field Types

| Field Type | Description |
|---|---|
| **Text** | Single-line or multi-line text input. Use for names, addresses, notes, and free-form responses. |
| **Number** | Numeric input with optional minimum, maximum, and decimal-place constraints. |
| **Date** | Date picker with optional date range restrictions. Supports date-only or date-and-time input. |
| **Dropdown** | Single-select list of predefined options. Options can be entered manually or pulled from a connected data source. |
| **File Upload** | Allows the user to attach one or more files. Configure accepted file types (e.g., PDF, JPEG) and maximum file size. |
| **Signature** | Captures a drawn or typed digital signature from the user. |
| **Checkbox** | Single checkbox for boolean yes/no values, or a checkbox group for multi-select options. |

## Adding Validation Rules

Validation rules ensure the data collected meets your requirements before a form can be submitted. To add a rule to a field:

1. Click the field on the canvas.
2. Open the **Validation** tab in the settings panel.
3. Click **Add Rule** and select a rule type.

Available validation rules include:

- **Required** — the field must have a value before the form can be submitted.
- **Minimum / Maximum length** — for text fields, restrict the number of characters.
- **Minimum / Maximum value** — for number fields, set acceptable numeric bounds.
- **Pattern match** — validate against a regular expression (e.g., for ABN or phone number formats).
- **Accepted file types** — for file upload fields, restrict to specific extensions.
- **Date range** — for date fields, restrict to past dates, future dates, or a specific window.

Each rule can include a custom error message that is shown to the user when validation fails.

## Conditional Logic

Conditional logic lets you show or hide fields based on the values entered elsewhere in the form. This keeps forms clean and relevant, surfacing only the fields each user needs to complete.

<Steps>
  <Step title="Open the conditional logic panel">
    Click the field you want to show or hide conditionally. Select the **Logic** tab in the settings panel.
  </Step>
  <Step title="Set the visibility rule">
    Choose **Show this field if** or **Hide this field if**.
  </Step>
  <Step title="Define the condition">
    Select the **source field** (the field whose value drives the logic), the **operator** (equals, does not equal, contains, is greater than, etc.), and the **value** to compare against.
  </Step>
  <Step title="Chain multiple conditions">
    Add more than one condition and connect them with **AND** or **OR** logic as required.
  </Step>
  <Step title="Save">
    Click **Apply Logic**. The rule is shown as a summary badge on the field in the canvas view.
  </Step>
</Steps>

**Example:** Show a *Supplier ABN* text field only when the *Respondent Type* dropdown is set to **Business**.

## Previewing and Testing Your Form

Click the **Preview** button at the top of the form builder to open a live preview of your form. You can fill in values and test conditional logic, validation messages, and field behaviour before publishing.

<Tip>
  Test your form using edge-case inputs — empty required fields, out-of-range numbers, and invalid file types — to make sure your validation messages are clear and helpful.
</Tip>

## Assigning a Form to a Portal

<Steps>
  <Step title="Open the portal settings">
    Navigate to **Configuration → Portals** and select the portal you want to update.
  </Step>
  <Step title="Add the form">
    Under the **Forms** section, click **Add Form** and select your form from the list.
  </Step>
  <Step title="Set the form position">
    Choose where the form appears in the portal: as a standalone page, a tab, or embedded within a specific workflow step.
  </Step>
  <Step title="Save">
    Click **Save Portal Settings**. The form is now live for users accessing that portal.
  </Step>
</Steps>

## Form Submission Actions

When a user submits a completed form, you can trigger one or more automated actions. Configure these under the **Submission Actions** tab of your form:

| Action | What it does |
|---|---|
| **Create a Record** | Automatically creates a new record (e.g., a Purchase Order or Contact) in the linked module using the form data. |
| **Trigger Notification** | Sends an email or in-app alert to one or more recipients with the submitted form data. |
| **Generate PDF** | Produces a formatted PDF document from the submission and attaches it to the record or emails it to a recipient. |
| **Start Approval Workflow** | Routes the submission through an assigned approval profile for review before the record is finalised. |

<Tip>
  When you have built a form that works well for a common use case — such as a supplier onboarding form or a returns request — save it as a **Template** using the **Save as Template** option in the form builder menu. You and your team can then create new forms from that template and customise them, rather than starting from scratch each time.
</Tip>
