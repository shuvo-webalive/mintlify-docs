Tasks are units of work in Exsited, with a checklist, assignees, notes and attached files. You can create, list, retrieve, update and delete tasks, manage their checklist items, and add, read, change and remove notes and note files. This area has 18 endpoints, each available in all seven SDKs.

<Warning>
  **Adding a note to a task currently fails.** `POST /tasks/{task_code}/notes` returns `409`, so the calls that need an existing note (read, update and delete a note, and list, read and delete its files) have not been confirmed to work. Deletes in this area cannot be undone; a deleted task returns `404`.
</Warning>

## Before you call

Register your API credentials once when your app starts, as shown in
[Authentication](/authentication). Every SDK sample on these pages then gets its client in one line.
With cURL, send the access token in an `Authorization` header: `Authorization: Bearer $ACCESS_TOKEN`.

## Things to know

- **Task bodies go under `work_task`.** The create and the update wrap their fields in `work_task`, `name` is required to create, and a key the API does not know is refused.
- **The note routes take the task's `code`, not its `wt_` id.** A `wt_` id returns `404` on every `/notes` path; the task, checklist and update calls take the `wt_` id.
- **Checklist bodies go under `checklist`.** Adding items sends an array of `{"name": ...}`; updating one item sends a single object. Most checklist calls return the whole task under `work_task`.
- **`checklist` changes shape.** It is an array on the task and on the checklist list, and a single object when you retrieve one checklist item.
- **Notes are multipart forms.** Send the text as the `note` field and, optionally, a `file`. To read an attached file's details, use the `uuid` from the note's file list; the call returns the file's details, not its contents.
- **A `COMPLETED` checklist item cannot be deleted.** The delete returns `409`.
