Each webhook delivery carries a `whk_` id, and you can read one delivery by that id. No endpoint lists deliveries. This area has 1 endpoint, and all seven SDKs call every one.

## At a glance

| Endpoint | Method | Path | What it does |
| --- | --- | --- | --- |
| [Retrieve a webhook delivery](/api-reference/webhooks/retrieve-a-webhook-delivery) | <span style={{fontFamily: "var(--font-mono, monospace)", fontSize: "0.72rem", fontWeight: 700, letterSpacing: "0.02em", color: "#0f7b6c"}}>GET</span> | `/webhooks/{webhook_id}` | Returns one webhook delivery by its `whk_` id. |

## Before you call

Register your API credentials once when your app starts, as shown in
[Authentication](/authentication). Every SDK sample on these pages then gets its client in one line.
With cURL, send the access token in an `Authorization` header: `Authorization: Bearer $ACCESS_TOKEN`.

## Things to know

- **Deliveries are read one at a time by their `whk_` id.** `GET /webhooks` without an id is refused, so keep the id each delivery carries.
- **A well formed id is `whk_` followed by 32 characters.**
- **An unknown id returns `404` with the code `resource_not_found`.**
