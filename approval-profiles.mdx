Approval profiles decide which transactions need approval and who approves them. You can list, create, read, update and delete them. This area has 5 endpoints, and all seven Exsited SDKs call every one.

<Warning>
  **An approval profile gates every matching transaction while it exists.** Create one only when those transactions should wait for approval.
</Warning>

## Before you call

Register your API credentials once when your app starts, as shown in
[Authentication](/authentication). Every SDK sample on these pages then gets its client in one line.
With cURL, send the access token in an `Authorization` header: `Authorization: Bearer $ACCESS_TOKEN`.

## Things to know

- **Five fields are required to create a profile.** `name`, `entity`, `event`, `approver_type` and `approver`.
- **A profile takes effect as soon as it exists.** It gates every matching transaction until it is deleted or its status changes.
- **Approval profile ids start with `ap_`.** One profile comes back under `approval_profile`.
- **A profile in use cannot be deleted.**
- **Listings page by cursor.** Records sit under `data`; pass `pagination.next_cursor` as `cursor` to read the next page, and stop when `pagination.has_more` is `false`.
