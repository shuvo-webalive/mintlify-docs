Custom events are events you define on top of a system event, for workflows and messages to react to. You can list, create, read, update and delete them. This area has 5 endpoints, and all seven SDKs call every one.

<Warning>
  **Creating a custom event adds a disabled message to every communication profile, and deleting the event leaves those messages behind.** The create, update and delete have not been confirmed, because no endpoint returns the `se_` id that `base_event` needs.
</Warning>

## Before you call

Register your API credentials once when your app starts, as shown in
[Authentication](/authentication). Every SDK sample on these pages then gets its client in one line.
With cURL, send the access token in an `Authorization` header: `Authorization: Bearer $ACCESS_TOKEN`.

## Things to know

- **`name` and `base_event` are required to create a custom event.** `base_event` is an `se_` id, not the `evt_` id the system events listing shows, and no listed id is accepted.
- **Custom event ids start with `ce_`.** One custom event comes back under `custom_event`.
- **A custom event in use cannot be deleted.** Only an event no workflow uses can be removed.
- **Listings page by cursor.** Records sit under `data`; pass `pagination.next_cursor` as `cursor` to read the next page, and stop when `pagination.has_more` is `false`.
