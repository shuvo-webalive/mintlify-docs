A communication profile holds a set of messages and channel settings that accounts use. Here you list, create, read, update and delete profiles. This area has 5 endpoints, and every SDK supports all of them.

<Warning>
  **Creating a communication profile currently fails.** `POST /settings/communication_profiles` returns `500` and creates nothing, so you can update and delete only profiles that already exist.
</Warning>

## At a glance

| [Create a communication profile](/api-reference/communication-profiles/create-a-communication-profile) | <span style={{fontFamily: "var(--font-mono, monospace)", fontSize: "0.72rem", fontWeight: 700, letterSpacing: "0.02em", color: "#2563eb"}}>POST</span> | `/settings/communication_profiles` | Creates a communication profile and returns it under `communication_profile`. |

## Before you call

Register your API credentials once when your app starts, as shown in
[Authentication](/authentication). Every SDK sample on these pages then gets its client in one line.
With cURL, send the access token in an `Authorization` header: `Authorization: Bearer $ACCESS_TOKEN`.

## Things to know

- **Each profile's id starts with `cmp_`.** List communication profiles returns each profile's `id`.
- **`name` is required to create a profile.** Its messages are copied from the profile in `copy_from`, or from the default profile.
- **One profile comes back under `communication_profile`; a listing comes back under `data`.** A listing also carries `pagination`; pass `pagination.next_cursor` as `cursor` while `has_more` is `true`.
- **The default profile cannot be deleted.** A delete marks the profile deleted, and reading it then returns `404`.
