An item fulfillment records items sent against the lines of a sale invoice. These endpoints create, list, read, update and delete fulfillments, and add, list, read and delete their notes. This area has 9 endpoints, and all seven SDKs call every one.

<Warning>
  **A fulfillment cannot be deleted once any of its stock has been sent.** The delete is refused with `400` `stock_committed`.
</Warning>

## Before you call

Register your API credentials once when your app starts, as shown in
[Authentication](/authentication). Every SDK sample on these pages then gets its client in one line.
With cURL, send the access token in an `Authorization` header: `Authorization: Bearer $ACCESS_TOKEN`.

## Things to know

- **Writes are wrapped in `item_fulfillment`.** A create names the sale invoice in `invoice_id` and lists `fulfillments`, each with an `invoice_line` id and a `fulfillment_quantity`.
- **Fulfillment ids start with `ifm_`, and note ids with `note_`.** Pass them in the paths as they are.
- **Notes are stored on the fulfillment's sale invoice.** The notes listing returns the invoice's notes, and a single note read comes back under `item_fulfillment.note`.
- **Deleting a note looks on the fulfillment itself.** A note added through the create note endpoint is stored on the invoice, so that delete does not find it.
- **A new fulfillment comes back with `fulfillment_status` `shipped`.** Each update raises its `version`.
- **The listing pages by cursor.** Pass `limit`, then send the `next_cursor` from `pagination` as `cursor` until `has_more` is `false`.
