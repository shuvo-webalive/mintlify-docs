title: "Introduction"
description: "The Exsited v4 REST API and the seven SDKs that call it."
---

The Exsited **v4 REST API** lets you read and change your Exsited data from your own code: accounts,
orders, invoices, payments, items, purchasing, work and settings. Seven SDKs, one per language, call
it for you with the same set of functions, so what you learn in one SDK applies to the others. These
docs cover only the endpoints that **all seven SDKs implement**: if a call is documented here, you can
make it from any of them.

Every SDK sends a JSON request body and gives you the JSON response body back, with the API's own
field names. Nothing is renamed or reshaped in either direction.

## What every SDK does for you

<CardGroup cols={2}>
  <Card title="Signs in for you" icon="key">
    Exchanges your API credentials for an access token, caches it and renews it before it expires.
  </Card>
  <Card title="One client for everything" icon="cubes">
    Each area, such as accounts, has one function per endpoint, for example
    `client.accounts.get_account("W13ZGY")` in Python.
  </Card>
  <Card title="JSON in, JSON out" icon="brackets-curly">
    You send the request body as a map or a JSON string, and read the decoded JSON response. You
    can also read the response as a typed object if you prefer.
  </Card>
  <Card title="Errors you can read" icon="triangle-exclamation">
    A failed call gives you the API's error body: its `code`, `message`, the `request_id` to quote to
    support, and one entry per field that failed.
  </Card>
</CardGroup>
