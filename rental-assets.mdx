Rental assets are the things customers can hire, each priced and scheduled by a rental asset profile. These endpoints list, create, update, cancel, reactivate and delete assets and profiles, and read and set each asset's availability. The module has 14 endpoints, and all seven SDKs call every one.

## Before you call

Register your API credentials once when your app starts, as shown in
[Authentication](/authentication). Every SDK sample on these pages then gets its client in one line.
With cURL, send the access token in an `Authorization` header: `Authorization: Bearer $ACCESS_TOKEN`.

## Things to know

- **Single records come back under `rental_asset` or `rental_asset_profile`.** Listings put their records under `data`.
- **`rental_asset_uuid` and `rental_asset_id` take the same value.** Both are the rental asset's `id`; the cancel and reactivate paths name it `rental_asset_id`.
- **Every session of a new profile needs a price.** A session with no `rental_asset_profile_session_prices` is refused with `400`.
- **Update rental asset availability takes a list and returns no body.** It returns `204`; read the asset to see the stored hours.
- **Cancel sets `status` to `inactive` and reactivate sets it to `active`.** Both take an empty object as the body, and cancelling an already cancelled asset is refused.
- **Listings page by cursor.** Pass `limit` and the previous page's `pagination.next_cursor` as `cursor`, and stop when `has_more` is `false`.
