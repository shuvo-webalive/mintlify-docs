Connecting Exsited to Shopify creates a live link between your online store and your operations platform. When a customer places an order on Shopify, Exsited picks it up immediately, updates inventory levels across all connected channels, and routes the order through your fulfilment workflow. Equally, product updates and stock adjustments made in Exsited flow back to Shopify in real time — so your store always reflects accurate availability. This bidirectional, real-time sync is designed to prevent overselling and reduce the manual overhead of managing orders across systems.

## Prerequisites

Before connecting Shopify, make sure you have:

- A **Shopify** store (any plan) with **Admin** access. You must be a store owner or have the **Apps and channels** permission enabled for your staff account.
- An Exsited account with the **Admin** role.
- Products in Exsited and Shopify that share a common identifier — typically a **SKU** — so Exsited can match records between the two systems.

## Connecting Shopify to Exsited

<Steps>
  <Step title="Navigate to the Shopify integration">
    In your Exsited dashboard, go to **Integrations → eCommerce → Shopify**. Click **Connect Shopify** to begin the setup.
  </Step>
  <Step title="Enter your store URL and API credentials">
    Enter your Shopify store URL in the format `your-store.myshopify.com`. Then choose your authentication method:

    - **Custom app (recommended)** — create a custom app in your Shopify Admin under **Apps → Develop apps**, generate an **Admin API access token**, and paste it into Exsited. This method gives you granular control over the API scopes granted.
    - **Shopify OAuth** — use Exsited's built-in OAuth flow for a faster setup. Click **Authorise via Shopify** and approve the permission request in your Shopify Admin.

    <Warning>
      The Shopify Admin API access token is shown only once when generated. Copy it immediately and store it securely before closing the Shopify app creation screen.
    </Warning>
  </Step>
  <Step title="Configure product and order sync settings">
    Once connected, configure what you want to sync and how:

    - **Product sync** — choose whether Exsited pushes new products to Shopify, pulls Shopify products into Exsited, or both.
    - **Order sync direction** — typically Shopify → Exsited (orders flow into Exsited for fulfilment), but you can also push Exsited-originated orders to Shopify for record-keeping.
    - **Order status trigger** — choose which Shopify order statuses Exsited processes (for example, **Paid** only, or **All open orders**).
    - **Fulfilment updates** — enable Exsited to push fulfilment status and tracking numbers back to Shopify so customers receive accurate shipping notifications.
  </Step>
  <Step title="Map fields">
    Use the visual field mapping screen to connect Exsited fields to Shopify fields. At minimum, confirm:

    - **SKU** — map Exsited product SKU to Shopify variant SKU. This is the primary match key.
    - **Stock location** — if you use multiple Shopify locations, map each Exsited warehouse to the corresponding Shopify location.
    - **Price** — map Exsited sale price to Shopify variant price. Choose whether tax is included in the price or added at checkout.
    - **Order reference** — map the Shopify order number to the Exsited order reference field.

    <Tip>
      If you sell product bundles in Shopify, map bundle SKUs to their Exsited equivalents and enable **Component inventory deduction** so Exsited reduces stock for each component when a bundle is sold.
    </Tip>
  </Step>
  <Step title="Enable real-time sync">
    Toggle **Real-time sync** on. Exsited installs webhooks in your Shopify store to receive instant notifications for order creation, order cancellation, inventory updates, and fulfilment events. Click **Save and Activate** to go live.
  </Step>
</Steps>

## What Syncs

| Data Type | Direction | Notes |
|---|---|---|
| Products | Bidirectional | Matched by SKU; new products can be pushed or pulled |
| Product variants | Bidirectional | Each variant mapped by its individual SKU |
| Inventory levels | Bidirectional | Real-time updates on every sale or stock adjustment |
| Orders | Shopify → Exsited | Pulled on order creation or when trigger status is met |
| Fulfilment status | Exsited → Shopify | Tracking numbers and carrier details pushed back to Shopify |
| Order cancellations | Shopify → Exsited | Cancellations trigger stock reversal in Exsited |

## Sync Direction Options

Exsited supports flexible sync directions for each data type. You can configure these individually:

- **Shopify → Exsited** — use Shopify as the source of truth. Products and orders created in Shopify flow into Exsited.
- **Exsited → Shopify** — use Exsited as the source of truth. Product updates, price changes, and stock adjustments in Exsited are pushed to Shopify.
- **Bidirectional** — changes in either system are reflected in the other. Use conflict resolution settings to define which system wins when updates occur simultaneously.

## Avoiding Overselling with Real-Time Stock Updates

Real-time inventory sync is the most important safeguard against overselling. When Exsited receives a new Shopify order, it immediately deducts the sold quantity from the available stock level and updates Shopify's inventory in return. If stock reaches zero, Exsited can automatically set the Shopify variant to **Continue selling: false** (deny purchase) to prevent further orders.

<Info>
  To enable automatic out-of-stock blocking, go to **Integrations → eCommerce → Shopify → Inventory Settings** and turn on **Auto-block when stock reaches zero**. This setting applies per product variant.
</Info>

For businesses selling across multiple channels (for example, Shopify and eBay simultaneously), Exsited uses a central inventory pool. Every channel draws from the same stock count, so a sale on any channel immediately reduces availability on all others.

## Troubleshooting

<AccordionGroup>
  <Accordion title="Webhook delivery failures">
    If Exsited is not receiving order or inventory events from Shopify, the webhooks may have been deleted or are failing to deliver. Navigate to **Integrations → eCommerce → Shopify → Webhooks** and click **Reinstall Webhooks** to recreate them. You can also check webhook delivery health in your Shopify Admin under **Settings → Notifications → Webhooks**.
  </Accordion>
  <Accordion title="SKU mismatches — products not matching">
    If Exsited cannot find a matching product for a Shopify order line item, it will log a "SKU not found" error. This usually means the SKU in Shopify differs from the SKU in Exsited. To resolve this, check the affected variant in Shopify and compare it to the product record in Exsited. Update the SKU in one system to match the other, then click **Retry Failed Orders** in the sync log.
  </Accordion>
  <Accordion title="Inventory levels out of sync after a bulk update">
    If you have performed a bulk stock adjustment in Exsited or a bulk import in Shopify, a full re-sync may be needed. Navigate to **Integrations → eCommerce → Shopify → Inventory** and click **Force Full Inventory Sync** to push the current Exsited stock levels to Shopify for all products.
  </Accordion>
  <Accordion title="Orders not appearing in Exsited">
    Check that the Shopify order status matches the trigger status configured in Exsited. For example, if Exsited is set to pull **Paid** orders only, orders with a **Pending** payment status will not appear. Adjust the order status trigger under **Integrations → eCommerce → Shopify → Order Settings** if needed.
  </Accordion>
</AccordionGroup>

<Note>
  For help with Shopify-specific errors, check the **Sync Log** under **Integrations → eCommerce → Shopify → Logs**. Contact [support@exsited.com](mailto:support@exsited.com) with the log reference for faster resolution.
</Note>
