Roles are the settings records for user roles, and each says whether it is a system role. You can list, read, create, update, enable or disable and delete roles. This area has 5 endpoints, and all seven SDKs call every one.

<Warning>
  **Known issue: creating or updating a role currently returns `500` after the role is saved.** List the roles to check before you retry.
</Warning>

## At a glance

| Endpoint | Method | Path | What it does |
| --- | --- | --- | --- |
| [List roles](/api-reference/roles/list-roles) | <span style={{fontFamily: "var(--font-mono, monospace)", fontSize: "0.72rem", fontWeight: 700, letterSpacing: "0.02em", color: "#0f7b6c"}}>GET</span> | `/settings/roles` | Returns a page of roles under `data`, with paging details under `pagination`. |
| [Create a role](/api-reference/roles/create-a-role) | <span style={{fontFamily: "var(--font-mono, monospace)", fontSize: "0.72rem", fontWeight: 700, letterSpacing: "0.02em", color: "#2563eb"}}>POST</span> | `/settings/roles` | Creates a role and returns it under `role`. |
| [Retrieve a role](/api-reference/roles/retrieve-a-role) | <span style={{fontFamily: "var(--font-mono, monospace)", fontSize: "0.72rem", fontWeight: 700, letterSpacing: "0.02em", color: "#0f7b6c"}}>GET</span> | `/settings/roles/{role_id}` | Returns one role by its `id`, under `role`. |
| [Delete a role](/api-reference/roles/delete-a-role) | <span style={{fontFamily: "var(--font-mono, monospace)", fontSize: "0.72rem", fontWeight: 700, letterSpacing: "0.02em", color: "#c2410c"}}>DELETE</span> | `/settings/roles/{role_id}` | Deletes a role. A system role is refused. |
| [Update a role](/api-reference/roles/update-a-role) | <span style={{fontFamily: "var(--font-mono, monospace)", fontSize: "0.72rem", fontWeight: 700, letterSpacing: "0.02em", color: "#7a5af8"}}>PATCH</span> | `/settings/roles/{role_id}` | Changes a role, or enables or disables it. |

## Before you call

Register your API credentials once when your app starts, as shown in
[Authentication](/authentication). Every SDK sample on these pages then gets its client in one line.
With cURL, send the access token in an `Authorization` header: `Authorization: Bearer $ACCESS_TOKEN`.

## Things to know

- **Responses wrap a role in `role`.** A single read returns `{"role": {...}}`.
- **`is_system_role` marks the built-in roles.** A delete of a system role is refused.
- **Listings page by cursor.** Records sit under `data`; pass `pagination.next_cursor` as `cursor` to read the next page, and stop when `pagination.has_more` is `false`.
