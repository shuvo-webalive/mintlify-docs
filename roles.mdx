Roles are the settings records that group user permissions, and each says whether it is a system role. You can list, read, create, update, enable or disable and delete roles. This area has 5 endpoints, and all seven SDKs call every one.

<Warning>
  **A create or an update saves the role and then returns a `500`, so check the roles listing before you retry.**
</Warning>

## Before you call

Register your API credentials once when your app starts, as shown in
[Authentication](/authentication). Every SDK sample on these pages then gets its client in one line.
With cURL, send the access token in an `Authorization` header: `Authorization: Bearer $ACCESS_TOKEN`.

## Things to know

- **Responses wrap a role in `role`.** A single read returns `{"role": {...}}`.
- **`is_system_role` marks the built in roles.** A delete of a system role is refused.
- **A create or an update reports an error after it saves.** The change is stored even though the status is `500`, so list the roles to find the record.
- **Listings page by cursor.** Pass `limit` for the page size, then pass `pagination.next_cursor` back as `cursor` while `pagination.has_more` is true.
