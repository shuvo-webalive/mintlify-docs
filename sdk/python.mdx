The Exsited Python SDK gives you a clean, Pythonic interface to the entire Exsited API. You handle your business logic; the SDK takes care of OAuth 2.0 authentication, token lifecycle, request retries, and error parsing. This guide walks you through installation, configuration, and common usage patterns to get you productive quickly.

## Prerequisites

Before you install the SDK, make sure your environment meets the following requirements.

- **Python 3.12 or later** — the SDK uses modern type hints and language features that require 3.12+
- **pip** — the standard Python package installer, included with all current Python distributions
- **Exsited API credentials** — a `client_id`, `client_secret`, and `redirect_uri` from your Exsited account manager

## Installation

Install the SDK from PyPI with a single command.

```bash
pip install exsited
```

To pin the SDK to a specific version in a `requirements.txt` or `pyproject.toml`, use the standard pip constraint syntax (for example, `exsited>=1.0.0`).

## Configuration

Create a dedicated configuration file to hold your credentials and SDK setup. Keeping this separate from your application logic makes it easy to swap credentials between environments.

```python config.py
from exsited.exsited.auth.dto.token_dto import RequestTokenDTO
import os

class CommonData:
    @staticmethod
    def get_request_token_dto():
        return RequestTokenDTO(
            grantType="client_credentials",
            clientId=os.environ["EXSITED_CLIENT_ID"],
            clientSecret=os.environ["EXSITED_CLIENT_SECRET"],
            redirectUri=os.environ["EXSITED_REDIRECT_URI"],
            exsitedUrl=os.environ["EXSITED_URL"],
        )
```

<Tip>
  Never hardcode credentials directly in your source code. Read them from environment variables (as shown above) or a secrets manager so they stay out of version control.
</Tip>

## Using the SDK

The examples below show the most common operations. All of them start by importing and initialising the SDK with your configuration.

### Authenticate

Import the SDK and create a client instance using the `RequestTokenDTO` from your config file. The SDK exchanges your credentials for an access token automatically.

```python
from exsited.exsited.exsited import ExsitedSDK
from config import CommonData

sdk = ExsitedSDK(CommonData.get_request_token_dto())
```

You only need to initialise the SDK once per session. The client handles token refresh internally whenever the current token expires.

### List Accounts

Retrieve all accounts and iterate over the results.

```python
accounts = sdk.account.list()

for account in accounts:
    print(account.name)
```

### Create an Item

Pass a dictionary of item attributes to `sdk.item.create()`. The SDK serialises the payload and returns the created item object.

```python
new_item = sdk.item.create({
    "sku": "WIDGET-001",
    "name": "Blue Widget",
    "price": 29.99
})

print(f"Created item: {new_item.sku} — {new_item.name}")
```

### Create an Order

Build an order payload with the required fields and call `sdk.order.create()`.

```python
new_order = sdk.order.create({
    "accountId": "ACC-1234",
    "lines": [
        {
            "itemSku": "WIDGET-001",
            "quantity": 3,
            "unitPrice": 29.99
        }
    ],
    "status": "draft"
})

print(f"Order created: {new_order.id}")
```

### Get Invoices

List all invoices, or filter by status or date range using optional parameters.

```python
# List all invoices
invoices = sdk.invoice.list()

# List only unpaid invoices
unpaid_invoices = sdk.invoice.list({"status": "unpaid"})

for invoice in unpaid_invoices:
    print(f"{invoice.id}: {invoice.totalAmount} due {invoice.dueDate}")
```

## Switching Environments

Point the SDK at a different Exsited instance by changing the `exsitedUrl` in your `RequestTokenDTO`. Use separate environment variable sets for each environment so your code stays identical.

```python
# Development
exsitedUrl = "https://dev.your-exsited-instance.com"

# Staging
exsitedUrl = "https://staging.your-exsited-instance.com"

# Production
exsitedUrl = "https://your-exsited-instance.com"
```

Set the appropriate `EXSITED_URL` environment variable before running your application and the SDK picks it up automatically.

## Error Handling

Wrap SDK calls in a `try/except` block to catch and handle errors gracefully. The SDK raises descriptive exceptions that include the HTTP status code and an explanation of what went wrong.

```python
try:
    account = sdk.account.get("ACC-NONEXISTENT")
except Exception as e:
    print(f"Error: {e}")
    # Example output:
    # Error: 404 Not Found — Account 'ACC-NONEXISTENT' does not exist.
```

<Note>
  The SDK automatically retries requests that fail due to transient network issues or server-side rate limiting. You only see an exception when the error is permanent or the retry limit is exhausted.
</Note>

For production applications, consider logging exceptions to your observability stack rather than printing them, so you can alert on patterns and debug with full context.
