The Purchase Orders API lets you create and manage the orders you place with your suppliers. A purchase order (PO) is a formal record of a request to a supplier to deliver specific items at an agreed price. Use this API to raise POs programmatically when stock levels fall below a threshold, track delivery status, and sync purchase data with an external accounting or ERP system to maintain accurate cost records.

## Endpoints

| Method | Endpoint | Description |
|--------|----------|-------------|
| `GET` | `/api/v3/purchase-orders` | List all purchase orders. |
| `POST` | `/api/v3/purchase-orders` | Create a new purchase order. |
| `GET` | `/api/v3/purchase-orders/{id}` | Retrieve a single purchase order. |
| `PATCH` | `/api/v3/purchase-orders` | Partially update one or more purchase orders. |
| `DELETE` | `/api/v3/purchase-orders` | Delete one or more purchase orders. |

## Purchase Order Statuses

| Status | Description |
|--------|-------------|
| `draft` | The PO has been created internally but not yet sent to the supplier. |
| `sent` | The PO has been transmitted to the supplier and is awaiting confirmation. |
| `received` | The goods or services have been received in full. |
| `cancelled` | The PO was cancelled before fulfilment. |

## List Purchase Orders

Retrieve a paginated list of all purchase orders.

```bash
curl https://example.exsited.com/api/v3/purchase-orders?limit=20&offset=0&order_by=created_on&direction=desc \
  -H "Authorization: Bearer <token>"
```

## Retrieve a Purchase Order

Fetch a single purchase order using its unique ID.

```bash
curl https://example.exsited.com/api/v3/purchase-orders/po_01HXYZ987 \
  -H "Authorization: Bearer <token>"
```

**Example response:**

```json
{
  "id": "po_01HXYZ987",
  "supplier_id": "sup_01HXYZ111",
  "status": "draft",
  "expected_date": "2025-03-15",
  "items": [
    {
      "item_id": "itm_01HXYZ456",
      "quantity": 100,
      "unit_cost": 22.50,
      "line_total": 2250.00
    },
    {
      "item_id": "itm_01HXYZ457",
      "quantity": 50,
      "unit_cost": 10.00,
      "line_total": 500.00
    }
  ],
  "total": 2750.00,
  "created_on": "2025-02-10T08:00:00Z"
}
```

<Note>
  Use `GET /api/v3/purchase-orders` with query parameters such as `supplier_id` or `status` to filter the list without fetching individual records.
</Note>

## Create a Purchase Order

Send a `POST` request with the supplier ID, line items, and the expected delivery date.

```bash
curl -X POST https://example.exsited.com/api/v3/purchase-orders \
  -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  -d '{
    "supplier_id": "sup_01HXYZ111",
    "status": "draft",
    "expected_date": "2025-03-15",
    "items": [
      {
        "item_id": "itm_01HXYZ456",
        "quantity": 100,
        "unit_cost": 22.50
      },
      {
        "item_id": "itm_01HXYZ457",
        "quantity": 50,
        "unit_cost": 10.00
      }
    ]
  }'
```

## Update a Purchase Order

Use `PATCH` to update the status, expected delivery date, or other fields on an existing PO.

```bash
curl -X PATCH https://example.exsited.com/api/v3/purchase-orders \
  -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  -d '{
    "id": "po_01HXYZ987",
    "status": "received",
    "expected_date": "2025-03-20"
  }'
```

## Delete a Purchase Order

```bash
curl -X DELETE https://example.exsited.com/api/v3/purchase-orders \
  -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  -d '{
    "ids": ["po_01HXYZ987"]
  }'
```

<Warning>
  Only purchase orders in `draft` status should be deleted. To cancel a PO that has already been sent to a supplier, update its status to `cancelled` using `PATCH` to preserve the audit trail.
</Warning>

<Note>
  When a PO moves to `received` status, Exsited can update the `stock_quantity` of each linked item automatically. This keeps your item catalogue accurate without requiring a separate stock adjustment call.
</Note>

## Request Fields

<ParamField body="supplier_id" type="string" required>
  The ID of the supplier account this purchase order is being placed with.
</ParamField>

<ParamField body="status" type="string">
  Initial PO status. Accepted values: `draft`, `sent`. Defaults to `draft`.
</ParamField>

<ParamField body="expected_date" type="string">
  The expected delivery date in `YYYY-MM-DD` format.
</ParamField>

<ParamField body="items" type="array" required>
  An array of line items being ordered from the supplier.

  <Expandable title="items fields">
    <ParamField body="items[].item_id" type="string" required>
      The ID of the catalogue item being ordered.
    </ParamField>
    <ParamField body="items[].quantity" type="integer" required>
      The number of units to order from the supplier.
    </ParamField>
    <ParamField body="items[].unit_cost" type="number">
      The agreed cost per unit from the supplier. Used to calculate the PO total and update cost-of-goods records.
    </ParamField>
  </Expandable>
</ParamField>

## Response Fields

<ResponseField name="id" type="string">
  The unique identifier for the purchase order, assigned by Exsited.
</ResponseField>

<ResponseField name="supplier_id" type="string">
  The ID of the supplier this PO was placed with.
</ResponseField>

<ResponseField name="items" type="array">
  The list of line items on the PO, each including `item_id`, `quantity`, `unit_cost`, and `line_total`.
</ResponseField>

<ResponseField name="status" type="string">
  Current status of the PO: `draft`, `sent`, `received`, or `cancelled`.
</ResponseField>

<ResponseField name="total" type="number">
  The total value of the purchase order based on quantities and unit costs.
</ResponseField>

<ResponseField name="expected_date" type="string">
  The expected delivery date in `YYYY-MM-DD` format.
</ResponseField>

<ResponseField name="created_on" type="string">
  ISO 8601 timestamp of when the purchase order was created.
</ResponseField>
