The Payments API lets you record and manage financial transactions against invoices in Exsited. When a customer pays an invoice — whether by card, bank transfer, or any other method — you record that payment here to close the loop on the billing cycle. Use this API to push payment confirmations from a payment gateway, reconcile settlements, issue refunds, or pull transaction data into an accounting system.

## Endpoints

| Method | Endpoint | Description |
|--------|----------|-------------|
| `GET` | `/api/v3/payments` | List all payment records. |
| `POST` | `/api/v3/payments` | Record a new payment. |
| `PATCH` | `/api/v3/payments` | Partially update one or more payment records. |
| `DELETE` | `/api/v3/payments` | Delete one or more payment records. |

## List Payments

Retrieve a paginated list of all payment records.

```bash
curl https://example.exsited.com/api/v3/payments?limit=20&offset=0&order_by=created_on&direction=desc \
  -H "Authorization: Bearer <token>"
```

## Record a Payment

Send a `POST` request to record a payment against an invoice. Provide the `invoice_id`, `amount`, payment `method`, and the `processed_at` timestamp.

```bash
curl -X POST https://example.exsited.com/api/v3/payments \
  -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  -d '{
    "invoice_id": "inv_01HXYZ321",
    "amount": 131.96,
    "method": "bank_transfer",
    "status": "completed",
    "processed_at": "2025-02-14T09:30:00Z"
  }'
```

<Tip>
  When a payment fully covers the outstanding balance on an invoice, Exsited automatically updates the invoice status to `paid`. You do not need to update the invoice separately.
</Tip>

## Update a Payment Record

Use `PATCH` to correct a payment record — for example, to update a `pending` payment to `completed` after settlement is confirmed.

```bash
curl -X PATCH https://example.exsited.com/api/v3/payments \
  -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  -d '{
    "id": "pay_01HXYZ654",
    "status": "completed"
  }'
```

## Delete a Payment Record

```bash
curl -X DELETE https://example.exsited.com/api/v3/payments \
  -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  -d '{
    "ids": ["pay_01HXYZ654"]
  }'
```

## Credit Notes and Refunds

To issue a credit note or record a refund, create a payment record with a negative `amount` value and set the `method` to `refund`. This reduces the outstanding balance on the associated invoice and creates a clear audit trail in your financial records.

```bash
curl -X POST https://example.exsited.com/api/v3/payments \
  -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  -d '{
    "invoice_id": "inv_01HXYZ321",
    "amount": -25.00,
    "method": "refund",
    "status": "completed",
    "processed_at": "2025-02-15T11:00:00Z"
  }'
```

<Note>
  Credit notes and refund records appear in your Exsited financial reports alongside standard payment entries, giving you a complete view of net receipts.
</Note>

## PCI-DSS Compliance

<Warning>
  The Payments API records payment metadata — amounts, methods, timestamps, and statuses. It does **not** store or transmit raw card data such as card numbers, CVVs, or expiry dates. Never send cardholder data to the Exsited API. Process card payments through a PCI-DSS-certified payment gateway and record only the resulting transaction reference and amount in Exsited.
</Warning>

## Request Fields

<ParamField body="invoice_id" type="string" required>
  The ID of the invoice this payment is applied against.
</ParamField>

<ParamField body="amount" type="number" required>
  The payment amount as a decimal. Use a negative value to record a refund or credit note.
</ParamField>

<ParamField body="method" type="string" required>
  The payment method used. Common values: `bank_transfer`, `credit_card`, `direct_debit`, `cash`, `refund`.
</ParamField>

<ParamField body="status" type="string">
  Payment status. Accepted values: `pending`, `completed`, `failed`. Defaults to `completed`.
</ParamField>

<ParamField body="processed_at" type="string">
  ISO 8601 timestamp of when the payment was processed. Defaults to the current time if omitted.
</ParamField>

## Response Fields

<ResponseField name="id" type="string">
  The unique identifier for the payment record, assigned by Exsited.
</ResponseField>

<ResponseField name="invoice_id" type="string">
  The ID of the invoice this payment is applied against.
</ResponseField>

<ResponseField name="amount" type="number">
  The payment amount. Negative for refunds or credit notes.
</ResponseField>

<ResponseField name="method" type="string">
  The payment method used.
</ResponseField>

<ResponseField name="status" type="string">
  Current status of the payment: `pending`, `completed`, or `failed`.
</ResponseField>

<ResponseField name="processed_at" type="string">
  ISO 8601 timestamp of when the payment was processed.
</ResponseField>
