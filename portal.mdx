The portal endpoints act for the people who sign in to your customer portal. You can log a portal user in, change or set their password, request a reset link, reset a password with a code, and activate or validate an account with a code. This area has 7 endpoints, and all seven SDKs call every one.

<Warning>
  **Setting a portal password by email does not ask for the current password, and the old password cannot be put back.**
</Warning>

## Before you call

Register your API credentials once when your app starts, as shown in
[Authentication](/authentication). Every SDK sample on these pages then gets its client in one line.
With cURL, send the access token in an `Authorization` header: `Authorization: Bearer $ACCESS_TOKEN`.

## Things to know

- **Every request body sits under a `portal` key.** A login, for example, sends `{"portal": {"email": "jane@example.com", "password": "current-password"}}`.
- **A portal user is an account with portal access.** Create the account with `grant_portal_access` set to `true` and a `grant_portal_password`, then log in with its `email_address` and that password.
- **A wrong password returns `400`.** After a password change, a login with the old password is refused.
- **A reset link request for an unknown email returns `202`.** The call does not fail when no portal user has that email.
- **Setting a password by email returns `202`.** `POST /portal/change` sends `email` and `password` under `portal`.
